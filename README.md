# 数据分析案例仓库

个人数据分析实战案例集合。每个案例一个独立目录，包含「数据清洗 → 探索分析 → 可视化 → 结论」的完整 Notebook 流程；另配一个本地案例管理平台，用于收录、检索和复盘。

## 案例一览

| 案例 | 数据来源 | 规模 | 分析内容 |
|---|---|---|---|
| [olist实战](olist实战/) | [Kaggle Olist 巴西电商](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) | 10 万订单 / 9 张关联表 | 客户分层、复购留存、履约诊断、差评归因、流失与销量预测（14 个 Notebook + HTML 报告） |
| [淘宝天猫用户行为分析](淘宝天猫用户行为分析/) | [天池 UserBehavior](https://tianchi.aliyun.com/dataset/649) | 1 亿条行为 / 98.8 万用户 / 9 天 | 流量趋势、转化漏斗、留存复购、商品品类结构（5 个 Notebook） |

## 目录结构

```
.
├── olist实战/                    # 电商订单数据：客户、履约、建模

├── 案例管理平台/                 # 本地案例管理平台（Vue3 + Element Plus + FastAPI + SQLite）
```

## 快速开始

### 分析环境

Python 3.12，公共虚拟环境在 `.venv/`：

```powershell
.venv\Scripts\activate
pip install pandas numpy matplotlib scikit-learn jupyter nbconvert nbclient
```

每个案例的标准流程：

1. 按该案例 README 的说明下载数据，放入 `源数据/`
2. 运行 `数据处理.ipynb`，生成 `data/` 下的清洗数据
3. 依次运行后续分析 notebook

### 案例管理平台

```powershell
cd 案例管理平台
启动平台.bat
```

后端 `:8000`、前端 `:5173`。把新的案例文件夹放到仓库根目录后，平台会自动扫描收录（自动读取文件夹名、README 首段作为简介、`requirements.txt` 作为技术栈），并检测已失效的案例路径。

## 数据管理约定

- **数据不入库**：`*.csv`、`*.zip`、`*.db`、`源数据/`、`data/` 都在 `.gitignore` 中忽略，仓库只保存代码与 Notebook
- **每个案例必须有 README**：说明数据来源、字段含义、分析结论，同时也是平台自动提取简介的依据
- **保证可复现**：README 里写清楚数据从哪里下载、放在哪个目录、跑哪个 notebook 生成中间表

## 结论速览

### olist 电商

93,358 名客户、复购率仅 3.0%，是典型的一次性交易平台；平均送达 12.1 天、准时率 93.2%，迟到订单差评率 61% vs 准时 9%——差评主因是物流而非商品；流失无法用首单特征预测（AUC 0.54）。详见 [案例 README](olist实战/README.md)。

### 淘宝用户行为

- **流量**：日均 PV 996 万、日均 UV 77.4 万；20-22 点贡献 24% 的浏览，是推送黄金时段
- **漏斗**：浏览→加购/收藏 87.3%，加购/收藏→购买 78.3%（该数据为用户筛选样本，绝对值不可外推至真实淘宝）
- **结构**：375 个品类（占 4%）贡献 80% 流量；416 万个商品中 84.6% 从未被购买，长尾极长
- **数据限制**：最后两天覆盖 98% 的用户，导致留存与复购指标失真，因此本项目不输出留存结论
